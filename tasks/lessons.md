# Lessons

Corrections and mistakes from past sessions, as rules. Loaded into every session by the
SessionStart hook; apply them before acting. Add one whenever the user corrects you or you
catch your own mistake. Merge or drop rules that turn out wrong or duplicate.
Format: `- YYYY-MM-DD — <what went wrong> → <rule>`

- 2026-09-25 — The architect reported "stop deletes the scratch copy" while the code only removed the keyring → before relaying a report's claim about cleanup or deletion, `ls` the path yourself.
- 2026-09-25 — `rsvpFillColor`/`rsvpTextColor` in Theme.qml passed a calendar color straight into `withAlpha`/`Contrast.readableOn`, both of which key off `c.r`; calendar colors are plain hex strings from `DankCalService` (JSON), not QML color objects, so `c.r` was always undefined — `withAlpha` silently returned transparent (killed the declined fill) and `Contrast.readableOn` read the fill as pure black (picked white text on any color) → when a value crosses from JSON/JS into a QML color-typed helper, normalize with `Qt.color()` at the call site and check `.r === undefined`, don't assume a "color" property is already a color object.
- 2026-09-25 — Tried `hyprctl dispatch sendshortcut`/`hyprctl repl 'hl.dsp.send_key_state(...)'` to drive the dev-instance calendar window by keyboard for a verification screenshot; `send_key_state` injects at the compositor/global level, not scoped to the target window, and one `m` keypress switched the real monitor's active workspace on the live desktop → never use `hyprctl`/`hl.dsp.*` key injection against a dev instance; it can act on the real session. Prefer `ipc ui.show view=<month|week|day|agenda>` for view navigation, and say "not reachable" per the brief rather than raw key injection when a state needs a click or keypress the IPC surface doesn't cover.
